# 07 — Progress storage

Everything is in `localStorage`, versioned, and tiny.

## Keys

| Key | Value |
| --- | --- |
| `brush:progress:v1` | `ProgressState` JSON (below) |
| `brush:draft:v1:<course>/<topic>/<slug>` | the editor draft string for that challenge |
| `brush:interview:v1` | last interview-mode setup (topics, count, time) |

Drafts are separate keys so the progress blob stays small and export/import can include or exclude them.

## Shape

```ts
interface ChallengeProgress {
  status: "solved" | "revealed" | "attempted";
  attempts: number;         // number of runs
  firstSolvedAt?: string;   // ISO
  lastRunAt: string;        // ISO
  solvedCode?: string;      // the code that passed, so "my solution" can be shown next to the author's
}

interface ProgressState {
  version: 1;
  challenges: Record<string, ChallengeProgress>;   // key = `${course}/${topic}/${slug}`
  solveDates: string[];                            // "YYYY-MM-DD" days with at least one solve, for streaks
}
```

`solved` is terminal: a later failed run does not downgrade it. `revealed` means the user opened the solution before passing; passing afterwards upgrades it to `solved` but the dashboard counts both as complete and shows revealed ones with a hollow tick on timelines.

## Store (`src/lib/progress.ts`)

- A module-level `state`, loaded lazily from storage on first subscribe, with a `Set` of listeners.
- `useProgress()` built on `useSyncExternalStore`; `getServerSnapshot` is unused (SPA) but the initial client snapshot is the parsed storage value, so there is no flash of "unsolved".
- Mutators: `recordRun(id, result, code)`, `markRevealed(id)`, `resetAll()`, `importState(json)`.
- Writes are synchronous to storage after each mutation. A `storage` event listener keeps multiple tabs in sync.
- Corrupt or unknown-version JSON is ignored and replaced with a fresh state (after logging a console warning).

## Derived data (`src/lib/stats.ts`, `src/lib/nextChallenge.ts`)

- `topicProgress(course, topic)` → `{ solved, total }` using the catalog counts.
- `courseProgress(course)`, `overallProgress()`.
- `streak()` from `solveDates` (consecutive days ending today or yesterday).
- `recentlySolved(n)`.
- `byDifficulty()` needs difficulty per challenge without loading every topic: the catalog includes a `difficulties: Difficulty[]` array per topic, generated by a script (`npm run gen:catalog`) and verified by the content test.
- `nextChallenge(from?)`: first unsolved in the current topic, else first unsolved in the next topic of the course, else first unsolved anywhere, else `null`.

## Export / import (`src/lib/exportImport.ts`)

- Export downloads `brush-up-progress-YYYY-MM-DD.json` containing `{ exportedAt, progress, drafts }`.
- Import reads a file, validates the shape with a hand-written guard (no schema library), shows a summary ("312 solved, 40 drafts, exported 2026-10-20"), and asks Merge or Replace. Merge keeps the later `lastRunAt` per challenge.
